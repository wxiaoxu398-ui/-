MedRAG 技术文档
1. 技术栈

层 选型 说明
后端框架 FastAPI 异步、自带 OpenAPI 文档
数据校验 Pydantic v2 请求/响应模型
ORM SQLModel 简单，SQLite 友好
数据库 SQLite 本地文件，零部署
向量库 ChromaDB 本地持久化
嵌入模型 BAAI/bge-small-zh-v1.5 中文，本地推理，约 100MB
关键词检索 rank_bm25 + jieba 中文分词 + BM25
重排 可选 bge-reranker-base 时间不够可跳过
LLM DeepSeek API（OpenAI 兼容） 中文好、便宜
PDF 解析 PyMuPDF (fitz) 文字版 PDF
SSE sse-starlette 流式输出
前端 Vue3 + Vite + TypeScript 组合式 API
UI 库 Naive UI 组件全，风格干净
Markdown markdown-it + highlight.js 答案渲染
HTTP fetch（原生） 不引 axios
状态 Pinia 会话、文档状态


不使用：LangChain / LlamaIndex（抽象多，调试难）。

3. 数据库设计（SQLite）


CREATE TABLE documents (
  id INTEGER PRIMARY KEY,
  title TEXT NOT NULL,
  author TEXT,
  source TEXT,
  license TEXT,
  file_name TEXT NOT NULL,
  file_path TEXT NOT NULL,
  num_pages INTEGER DEFAULT 0,
  num_chunks INTEGER DEFAULT 0,
  status TEXT DEFAULT 'pending',
  created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE chunks (
  id INTEGER PRIMARY KEY,
  document_id INTEGER NOT NULL,
  chunk_index INTEGER NOT NULL,
  content TEXT NOT NULL,
  page_start INTEGER,
  page_end INTEGER,
  section TEXT,
  FOREIGN KEY (document_id) REFERENCES documents(id)
);

CREATE TABLE conversations (
  id INTEGER PRIMARY KEY,
  title TEXT,
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE messages (
  id INTEGER PRIMARY KEY,
  conversation_id INTEGER NOT NULL,
  role TEXT NOT NULL,
  content TEXT NOT NULL,
  sources_json TEXT,
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (conversation_id) REFERENCES conversations(id)
);

CREATE TABLE feedback (
  id INTEGER PRIMARY KEY,
  message_id INTEGER NOT NULL,
  rating TEXT NOT NULL,
  comment TEXT,
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (message_id) REFERENCES messages(id)
);

CREATE INDEX idx_chunks_doc ON chunks(document_id);
CREATE INDEX idx_messages_conv ON messages(conversation_id);

Chroma 集合：med_chunks

• id：chunk_{chunk_id}
• embedding：bge-small-zh 输出
• metadata：{chunk_id, document_id, title, page_start, page_end}
• document：原文内容




4. RAG Pipeline
4.1 入库流程


PDF 文件
  ↓ PyMuPDF 提取文本（按页）
  ↓ 清洗（去页眉页脚、多余空白）
  ↓ 切块（见 4.2）
  ↓ 写入 SQLite chunks 表
  ↓ bge-small-zh 生成向量
  ↓ 写入 Chroma
  ↓ 更新 documents.status = 'ready'

4.2 切块策略
• 优先按标题切（正则：第.章、第.节、\d+\.\d+）
• 段落合并到 300～500 字
• 超过 600 字强制切
• 相邻块重叠 50 字
• 表格整块保留，不切
• 每块记录：page_start、page_end、section

4.3 检索流程


用户问题
  ↓ 查询改写（可选：提取关键词）
  ↓ 向量检索 top 10
  ↓ BM25 检索 top 10
  ↓ RRF 融合
  ↓ 去重
  ↓ 取 top_k（默认 6）
  ↓ （可选）reranker 重排
  ↓ 返回 Source 列表

RRF 公式：


score = Σ 1 / (k + rank_i)，k 取 60

4.4 生成流程


构造 prompt（见第 5 节）
  ↓ DeepSeek API 流式调用
  ↓ 逐 token 通过 SSE 推给前端
  ↓ 结束后保存 message + sources

4.5 拒答判断
• 若 top1 向量相似度 < 0.35 且 BM25 最高分 < 阈值 → 直接拒答
• 或让 LLM 在 prompt 中判断“资料是否足够”，返回特殊标记




5. Prompt 模板
5.1 系统提示词


你是医学学习助手，服务于医学生。

规则：
1. 只根据【参考资料】回答，不得使用你的先验知识。
2. 每个结论后必须标注来源编号，如 [1][2]。
3. 如果参考资料不足以回答，只回复：
   “根据当前资料无法确定，请查阅原始教材。”
4. 不提供诊断、处方、治疗方案。
5. 使用规范医学术语，必要时给出中英文对照。
6. 用 Markdown 输出，可用列表、表格。

5.2 用户提示词


【参考资料】
[1] 《生理学（第9版）》第112页：
心肌细胞动作电位分为5期：0期快速去极化...

[2] 《生理学（第9版）》第113页：
1期由K+外流引起...

【问题】
心肌细胞动作电位分几期？各期离子机制是什么？

8. 关键模块说明
8.1 ingest.py
• 扫描 BOOKS_DIR 下所有 .pdf
• 对每个文件：
• 计算 hash，跳过未变更的
• PyMuPDF 逐页提取
• 切块
• 批量嵌入（batch=32）
• 写 SQLite + Chroma

• 提供命令行入口：python -m app.rag.ingest

8.2 retrieve.py
• 单例加载 embedding 模型（避免重复加载）
• vector_search(query, k) → Chroma
• bm25_search(query, k) → 内存 BM25 索引
• hybrid_search(query, k) → RRF 融合
• BM25 索引在启动时从 SQLite 加载

8.3 generate.py
• 用 openai SDK，指向 DeepSeek base_url
• 异步流式：async for chunk in client.chat.completions.create(stream=True)
• 生成器 yield token
• 结束后解析引用编号，回填 sources

8.4 chat.py
• POST /api/chat/stream
• 用 EventSourceResponse
• 流程：检索 → 推送 sources → 流式生成 → 推送 delta → 保存 → done

10. 测试与评估
10.1 功能测试
• 空 PDF、扫描版 PDF、超长 PDF
• 无相关资料的问题 → 必须拒答
• 多轮追问
• 刷新页面后历史保留

10.2 效果评估
准备 eval/questions.json：


[
  {
    "question": "心肌细胞动作电位分几期？",
    "expected_source": "生理学 第112页",
    "expected_keywords": ["0期", "1期", "2期", "3期", "4期"]
  }
]

指标：

• 检索命中率：期望来源是否在 top_k 中
• 引用准确率：答案引用是否指向正确页
• 拒答准确率：无答案问题是否正确拒答

10.3 常见问题
• 扫描版 PDF 提不出字 → 提示用户换文字版
• 嵌入模型首次下载慢 → 提前下载到本地
• DeepSeek 超时 → 加重试 + 前端提示
• Chroma 与 SQLite 不一致 → 重建索引时两边一起清
