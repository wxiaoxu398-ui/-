# 启动修复与评审检查

## 这次处理的范围

用户反馈电脑重启后双击启动文件显示失败。旧启动流程存在几项会影响现场检查的设计风险：已有网页时仍要求 Node.js；普通启动可能安装依赖、重建网页；加载已有 BGE 模型仍可能访问网络；虚拟环境可能依赖原开发电脑的 Python 缓存路径；等待结束时的提示不足以区分具体问题。

这些是根据启动代码和当前环境确认的风险，不等于已经复现了用户当时看到的原始错误。没有替用户执行 Windows 真正的关机或重启。完整验证记录应分别说明本机停止后启动、离线启动、目录迁移和其他电脑检查的实际范围，不能把一次 HTTP 请求成功写成全部验收通过。

## 日常使用与首次准备

已准备好的这台电脑：双击项目根目录的 `start-medrag.cmd`。启动完成后，用本机 Chrome 或 Edge 打开 `http://127.0.0.1:8000/`。`127.0.0.1` 只指向当前电脑，不能作为评审在其他电脑访问的公网地址。电脑重启后需要重新启动本地服务。

在新电脑上使用源码包：先双击 `prepare-medrag.cmd`，按照准备窗口提示安装依赖、构建网页和准备模型。首次准备需要可用的 Python 和网络；网页构建还需要 Node.js。准备完成再使用 `start-medrag.cmd`。不要把开发电脑上的 `.venv` 直接复制到另一台电脑后当作独立运行时；它可能仍引用原电脑的解释器绝对路径。

评审运行包与源码包不同：运行包应带已构建网页、匹配的 Python 运行时与依赖、本地模型以及明确的启动入口。源码 ZIP 和 Git 历史包用于审查与复现开发，不能自动证明包含这些运行文件。旧材料包不会随着工作区代码修改而自动更新；修复后必须生成新的交付包，并从新目录解压验证。实际提供的运行包以其清单和检查结果为准。

离线可检查本地网页、文档与检索环境。DeepSeek 生成答案需要网络及使用者自己的有效 API Key；本地文件检查通过不等于该 API 已通过连通性或额度检查。没有密钥时应用可使用明确标注的原文摘录模式。

## 双击环境检查

双击根目录 `check-medrag.cmd`。检查器只读取必要的环境和运行文件，不联网、不安装、不启动服务、不读取会话数据库、不输出 API 密钥，也不加载大型模型权重。

检查包括：

- Python 是否为受支持的 3.11–3.13 版本。
- 核心依赖能否导入；BGE 依赖是否有模块和版本元数据。
- `frontend/dist/index.html` 直接引用的 `/assets/` 文件是否存在且非空。
- 当前检索配置是否可读取；BGE 模型的配置、分词器和权重是否在本地缓存或运行包中。

若未通过，窗口会保留结果，并尝试用记事本打开本说明。按具体项目运行 `prepare-medrag.cmd`，或重新解压完整运行包。检查器不要求 Node.js，不依赖开发机器的构建标记。

供自动检查调用：

```powershell
.venv\Scripts\python.exe scripts/check_environment.py --json
# 评审运行包使用：
runtime\python\python.exe scripts/check_environment.py --json
```

JSON 只包含 `ready` 和 `checks`，使用 ASCII 转义；成功退出码为 0，失败为 1。这是文件和依赖检查，不能替代实际模型加载、浏览器操作或医学内容核验。

## 打不开时如何定位

1. 从资源管理器进入项目文件夹，双击 `start-medrag.cmd`。不要只收藏网页地址后假定服务会自动运行。
2. 保留启动窗口显示的错误，查看窗口指出的 `.local` 启动日志，再双击 `check-medrag.cmd`。诊断时不要公开 `.env` 或完整私人会话数据。
3. 缺少 Python、依赖、网页或模型时，使用 `prepare-medrag.cmd`。如果 Python 文件存在却不能运行，应修复运行时，而不是反复点击网页刷新。
4. 若 8000 端口被其他软件占用，先确认是哪一个软件。不要为了启动作品而随意结束未知进程。
5. Windows 的“允许此应用”或安全软件提示应由电脑使用者核实后处理。不要关闭系统防护来掩盖启动失败。

## 提交前实际检查

应使用最终交付目录，完成以下检查并记录结果：

- 退出服务后重新双击启动，首页及引用的静态资源都能访问；重复启动能正确复用服务。
- 使用 Windows 自带 PowerShell 5.1、不同工作目录和包含中文、空格的解压路径运行入口。
- 对已准备环境验证不依赖 Node.js PATH、不在日常启动时临时安装软件；在断网条件下验证本地模型可加载。
- 从运行包解压的新目录验证。资料库应使用有许可的教材和新建的演示数据，不复制私人会话或真实 API Key。迁移目录后核对索引状态，必要时显式重新建立索引。
- 完成一次教材内提问、原页引用、追问、资料外拒答、刷新后会话保留和笔记导出。DeepSeek 检查应记录实际网络与 API 条件。
- 最后由团队在评审使用的电脑真正重启一次，再双击入口完成同样检查。尚未执行的项目应保留为待验，不写成已通过。

不要用“环境检查通过”“源码已打包”或“网页曾经打开过”代替最后一次真实交付检查，也不要承诺任何电脑都能在缺少运行文件时完全离线启动。
