# MedRAG 验收记录

日期：2026-10-11。运行环境：Windows、Python 3.12、CPU、BAAI/bge-small-zh-v1.5、Chroma 1.5.9；网页为 Vue 生产构建，服务仅监听 127.0.0.1:8000。

| Nursing Pharmacology 2e | 965 | 3,350 | 31a25bfc83a2 |
| Nursing Fundamentals 2e | 1,499 | 5,343 | 49743bf7d5a8 |

完整 SHA-256、作者、来源与许可证 URL 见 `eval/open-books.json`。归档原始下载约 715 MiB，PDF 共约 637 MiB；其中 Nursing Skills 超过网页上传限制，示例下载脚本直接写入文档目录。

## 检索与原页

`eval/open-book-questions.json` 含 10 个从原书手工选择的问题与预期物理页、3 个教材外问题。先通过 PDF 独立查找段落，随后才执行混合检索；没有从检索输出反推正确页。另用 Poppler 渲染药理学第 33 页、护理基础第 546 页、护理技能第 174 页进行视觉核对。

| 检查 | BGE + BM25 + RRF | BM25 |
| --- | ---: | ---: |
| 10 题前六条来源中包含预期页 | 10/10 | 10/10 |
| 首条来源为预期页 | 8/10 | 9/10 |
| 混合检索来源与 PDF 页及指纹一致 | 60/60 | — |
| 3 个教材外问题无检索结果 | 3/3 | 3/3 |
| 带上下文的追问命中预期页 | 通过 | 通过 |

这是**预期页召回率和原页映射**，不能当作生成答案的引用准确率。一个来源落在正确页不代表模型引用该页后说出的结论正确。基准为英文教材上的英文问题，不证明纯中文跨语言检索能力。

发现同一本护理技能教材的成人呼吸频率范围存在不一致：第 85 页与第 620/1413 页给出的范围不同。对应问题已保留核对备注；系统提示要求模型说明原文差异并分别引用。未通过真实 API 验证模型是否遵守。

## 稳定性修复

真实入库后再启动独立进程，发现中文路径下 Chroma 只有 SQLite 与元数据，原生 HNSW 文件未正确保存。将相同 1,200 条测试向量放入英文路径后，文件完整且独立进程可以重开。

修复后，Windows 中文项目路径自动映射到本机应用数据目录的英文向量缓存。`verify_persistence.py` 在两个独立进程中写入/重开 1,200 条向量并检查相同首条结果。启动和入库时校验向量数量及原生索引可读性；缺失索引的文档改为待入库，避免继续使用错误的“就绪”状态。

三本真实教材入库后，另一独立进程重开 12,978 条向量，再运行 10 题、拒答与追问检查，结果相同。期间模拟了入库中断，再以增量入库恢复三本就绪状态。CPU 计算限制为 4 个线程，给网页响应留出余量。报告中的 `index_seconds` 是当次运行的增量检查与预热时间，不能当作全量重建耗时。

## 自动化与页面

19 项后端测试通过，包括引用结构拦截、断流保存、文件更新/移走、目录扫描、上传、500 页解析、拒答、反馈与会话持久化、旧数据库增量迁移、摘录来源与展示内容一致，以及指定物理页预览。TypeScript 与生产构建通过。

内置浏览器中已检查正式文档库：三本均显示已入库；教材问题返回三段原文与三个来源编号；点击编号能展开相应来源、显示书名、页码、出处和许可证。停止并重启服务，再刷新网页，保存的会话、回答和引用仍可打开。

原生 PDF 查看器收到 `#page=33` 后仍停在末页，因此增加明确渲染物理页的预览。通过页面点击“打开原文”，实际显示 Nursing Pharmacology 2e 的 PDF 第 33 页 / 965 页，与独立渲染的原书第 33 页相同；其中印刷页为 21。上一页/下一页可在物理页之间切换，另保留完整 PDF 入口。预览与原始文件接口均校验历史引用的文件指纹，防止打开替换后的错误版本。

1440×900 桌面视口的三栏布局已核对；390 像素宽的原页预览没有横向溢出，原页图片正常加载。控制台未捕获页面错误。截图保存在 `.local/medrag-real-preview.jpg` 与 `.local/medrag-source33.jpg`。此次 UI 检查使用内置浏览器，未单独运行 Chrome 与 Edge 版本验收。

## 仍需完成的真实生成验收

DeepSeek 密钥未配置，因此以下标准尚未完成：

- 10 个教材问题的真实生成答案，每条结论被引用原页支持，人工准确率达到 80%。
- 多轮追问的生成质量，而不仅是检索上下文命中。
- 第一段展示小于 3 秒、完整有效回答小于 30 秒。
- API 实际 token 用量与账单证明单次低于 0.01 元。

`verify_real_corpus.py --live` 会使用在本机设置中填写的密钥，输出回答、引用、时间和 API 返回的 token 用量。费用只是使用当日官方高峰人民币单价的估算，需要与账单对照。没有用原文摘录或模拟 API 来替代这些验收项。

默认模型已更新为 `deepseek-flash` 并关闭思考模式；旧 `deepseek-chat` / `deepseek-reasoner` 在官方说明中已于 2026-07-24 停用。[官方变更](https://api-docs.deepseek.com/news/news260424/)、[当前价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
