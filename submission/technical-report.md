## 1. 项目概述与使用场景

MedRAG 面向医学生的教材阅读与复习，将导入资料中的原文、书名和 PDF 物理页连接到问答结果。用户可以查概念、整理知识点、围绕同一主题追问，也可以把原文转化为简短自测题。系统不把模型能够回答等同于资料能够支持：检索依据不足时，返回明确的资料不足说明；有依据时，要求实质性结论携带引用，并提供原页核对入口。

常见学习过程从一个教材问题开始。用户选定全库或若干本书，输入问题，查看带编号的回答，再从来源面板展开原文、打开对应物理页。需要复习时，可切换知识梳理或自测练习；自测答案默认折叠，避免直接展示参考答案影响回忆。学习过程保存为本机会话，也可导出带来源信息的 Markdown 笔记。

作品采用浏览器作为主要交互界面，后端只绑定 `127.0.0.1:8000`，不部署公网，不要求注册登录。设计对象是使用普通电脑、无需掌握命令行的学习者，因此提供双击启动脚本、网页 API 配置、文件导入、索引状态和错误提示。纯源码首次准备依赖、嵌入模型及开放资料需要网络；完整 Windows 评审运行包已带运行环境和指定公开资料。日常启动复用本地资源，配置 DeepSeek 后的生成环节仍需要网络。

医学内容的用途严格限定为学习参考。本系统不处理患者资料，不提供个人诊断、处方、剂量或治疗建议，也不承担临床决策支持。当前资料库是三本 Open RN 英文教材与四本中文专业学习手册或指南；中文资料不能视作国内医学本科统编教材。系统展示逐本来源与许可，资料是否适合导入仍需按原书授权核对。

## 2. 需求分析与实现范围

产品的核心需求是让回答可追溯、依据不足可识别、操作过程可理解。问答质量应同时考虑检索、生成、引用和人工核验，不能只用页面出现了一段流畅文字作为验收结果。页面保持左侧文档和会话、中间学习交互、右侧参考来源的结构，并在窄屏中使用可展开导航与来源面板。

| 需求类别 | 已实现行为 | 验证重点 |
| --- | --- | --- |
| 资料管理 | 目录扫描、网页上传、元信息编辑、增量及全量入库 | 状态反馈、文件变化、失败提示 |
| 教材问答 | 流式回答、来源编号、原文片段和原页预览 | 问题与本轮证据的对应关系 |
| 交互连续性 | 上下文追问、历史切换、刷新恢复、停止生成 | 保留部分内容及完成状态 |
| 学习整理 | 概念讲解、知识梳理、自测练习、Markdown 导出 | 学习材料继续受引用规则约束 |
| 可验证性 | 中文、英文与通用评估集，单题重测、人工标注和导出 | 区分原页命中、答案准确与拒答 |
| 使用边界 | 顶部声明、个人医疗请求拒答、来源与许可展示 | 不暗示提供医疗建议 |

原需求中的速度目标为首字响应小于 3 秒、完整回答小于 30 秒；当前实现按段落验证后输出，记录的是首个可展示段落耗时。两种计时口径需要区分。成本目标不能仅靠旧单价估算证明，运行报告保留模型返回的 token 用量，实际费用以服务商账单为准。

本版本没有用户系统、公网托管、患者数据、医学影像、浏览器端多模态推理、MCP 或 Function Calling。可选的纯 LLM 与 RAG 并排对比尚未实现。已有过程属于确定性的检索增强工作流，不描述为能够自主规划、任意调用外部工具的 Agent。

## 3. 系统架构与数据组织

前端使用 Vue 3、TypeScript、Vite 和 Pinia，Naive UI 提供弹窗等基础界面，Markdown-it 负责回答排版。FastAPI 提供本地 HTTP 与 SSE 接口，SQLModel/SQLite 保存结构化数据，Chroma 保存向量索引，PyMuPDF 负责逐页文本提取及原页渲染。DeepSeek 只接收本次调用需要的问题、近期上下文和检索片段。

```text
PDF 与来源许可
  -> PyMuPDF 逐页解析 -> 页内分块 -> SQLite 原文与页码
                              -> BGE 嵌入 -> Chroma 向量
问题与最近上下文 -> BM25 / 向量候选 -> RRF 融合与证据筛选
  -> 无依据则拒答；有依据则 DeepSeek 生成
  -> 逐段引用格式检查 -> SSE -> 浏览器回答与来源面板
  -> 文件 SHA-256 校验 -> PDF 物理页预览 -> 读者核验
```

<!-- figure: architecture -->

结构化存储包含文档、分块、会话、消息和反馈。文档记录文件名、作者、页数、许可、入库状态、文件指纹及索引方式。分块保存原文、章节线索、所属文档和起止物理页。消息保存回答文本、来源快照、完成状态及运行指标，因此历史引用不依赖当次检索排序仍保持不变。

| 层次 | 主要实现位置 | 职责 |
| --- | --- | --- |
| 交互与状态 | `frontend/src/App.vue`、`stores/workspace.ts` | 页面导航、会话、请求、中断与来源选择 |
| 学习与评估 | `components/MessageItem.vue`、`EvaluationPanel.vue` | 自测卡片、引用按钮、逐题评估及导出 |
| 本地接口 | `backend/app/api/` | 文档、设置、会话、问答和评估接口 |
| 检索生成 | `backend/app/rag/` | 解析分块、嵌入、融合检索、提示与校验 |
| 可复现依据 | `eval/`、`backend/tests/` | 资料指纹、独立原页标签、基准与隔离测试 |

SQLite 和向量索引各自承担不同职责。应用启动时检查已入库文档的向量条目数量，索引缺失或不可读时将文档改为待入库。Windows 中文路径下，原生 HNSW 文件映射至系统本地应用数据目录中的 ASCII 路径，避免本地索引不能可靠落盘；PDF 与 SQLite 仍留在项目目录。评审运行包另带与公开书目相符的向量种子，启动时可将其恢复至新路径的索引目录；这不等于通用备份，迁移后仍需检查资料就绪状态，新增或变更文件需重新入库。

## 4. AI 选型与检索生成方案

### 4.1 逐页解析与分块

文本按 PDF 物理页提取，使用阅读顺序排序。清理仅去除在多页边缘重复出现的短行，不合并物理页。`splitter.py` 默认以 480 字符为目标、50 字符重叠，在可用位置优先按换行或中文句号截断；片段不足目标长度时保留原有内容。每个片段的起止页均为当前物理页，章节名称只作为辅助线索。

这种设计使页码映射简单、可检查，避免跨页拼接后难以定位依据。代价是某些跨页表格、图注或长段落可能被拆开。无可提取文本、损坏或受密码保护的 PDF 会产生明确提示；本版本不内置 OCR，也不将扫描图像错误标为可检索文字。

### 4.2 混合候选与保守筛选

默认嵌入模型为 `BAAI/bge-small-zh-v1.5`，在 CPU 上运行，默认限制为 4 个计算线程。选用本地嵌入是为了将资料解析与检索留在本机，并以较小模型降低普通电脑的运行门槛。模型主要面向中文，系统没有把英文结果或混合语种结果视作已证明的中文跨语言能力。日常启动使用本地快照并限制本地文件加载，不因模型初始化自动下载；缺少快照时提示先运行准备入口。

BM25 使用分词后的字词计算词法相关性，向量检索补充语义相近候选。两路各取最多 10 个候选，用常数为 60 的 RRF 融合排序；默认返回最多 6 个来源。RRF 处理两类排序次序，不把它解释为概率或医学准确率。界面中的检索排序分仅用于帮助读者理解候选顺序。

候选进入生成前还需通过证据筛选。当前默认向量相似度阈值为 0.35、词覆盖阈值为 0.5、BM25 阈值为 1.5；定义型问题另检查原文中的术语定义行，较长问题中完全覆盖有效词的片段可优先排序。向量候选仍要求共享有效查询词，以减少重复医学术语造成的弱匹配。门槛按当前实现解释，不能脱离资料库规模当作通用可靠度标准。

这一策略偏向保守，可能拒绝同义词、缩写和跨语言表达。评估中保留没有命中独立原页标准的题目，后续优化应在固定标签上比较召回与误命中，不能根据检索结果反向修改标准以提高表面分数。

### 4.3 上下文与证据限定生成

会话最多携带最近 6 条已完成消息，通常对应最近 3 轮。检索阶段只对短问题或“它、上述、继续”等指代追问，拼接最近 2 条用户问题；明确的新问题独立检索。历史回答只用于理解上下文，不能作为本轮医学证据。这样可减少先前回答中的错误在后续轮次被直接继承。

默认生成模型为配置中的 `deepseek-flash`，温度为 0.2，最多生成 600 tokens，并显式关闭思考模式。来源和问题使用 JSON 边界传入，系统提示规定只能使用本轮资料、不得补入先验知识、每条实质性结论必须引用、资料不足时拒答，并禁止个人医疗建议。三种学习模式只是输出组织方式不同，共用证据与引用约束。

生成采用流式接收、按空行分段缓冲。每段检查引用编号是否存在及有效、每句是否附引用，并拦截无来源的自述与代码块；通过后才发送前端。复杂表格需要每个数据行携带引用。错误编号、缺少引用、超长或超时会停止输出，并保留已显示内容及未完成状态。格式通过只能证明结构符合规则，不能证明引用在语义上充分支持结论。

## 5. 核心前端交互与学习模式

主界面把操作和依据放在相邻区域。文档库显示作者、页数和状态，可筛选检索范围；聊天区接受问题、显示流式段落；来源面板展示书名、物理页、原文及许可。点击答案编号会定位来源，打开原页时按文档指纹检查文件版本。页面顶部固定显示学习用途声明，API 设置入口放在主页面顶部，窄屏下也能直接发现。

<!-- figure: study -->

概念讲解围绕问题解释定义和关键区别；知识梳理把证据组织成简短复习要点；自测练习生成两道题目及参考答案，题干和答案都要求来源。前端识别完整的自测格式后渲染卡片，参考答案可折叠展开；不满足结构的内容继续使用受限 Markdown 渲染，避免为追求卡片效果丢掉原有回答文本。

处理状态来自实际 SSE 事件。元信息确定会话和消息，来源事件更新候选，阶段事件展示开始整理答案或准备拒答，段落事件更新可展示内容，结束事件保存耗时和用量。证据路径显示检索片段数、检索耗时、通过格式检查的段落数及原页核验提醒。它展示系统执行状态，不显示或假称模型内部推理过程。

停止按钮通过 AbortController 中断请求；后端在清理阶段保存已生成内容和停止状态。正常完成、主动停止与出错分别呈现，不能把部分回答显示成完整结果。会话与消息保存在 SQLite，刷新可恢复已选择会话；页面位置使用简单哈希路由保存。评估与作品说明按需加载，并提供加载失败后的刷新入口。

学习笔记导出包含问题、回答、每条来源的书名、物理页、许可及文件指纹，不包含 API 密钥。评估可导出 JSON，记录题集、运行范围描述、问题、来源、耗时、错误和核验标注。针对窄屏，侧栏允许整列滚动，自测卡片和统计网格重排；本轮已检查 1440 像素桌面布局及 375 像素窄屏的关键页面。

## 6. 来源追溯、安全与可控性

每次入库计算 PDF 的 SHA-256，并在消息来源快照中保存该指纹、原文与物理页码。打开历史引用时重新检查原文件；原书被替换或移走后，历史片段可以保留，但不能把旧页码静默跳转至新版本。预览页明确标注从 1 开始的 PDF 物理页，提供翻页与完整 PDF 入口，避免把印刷页码与文件页序混为一谈。

固定拒答文本为“根据当前资料无法确定，请查阅原始教材。”。无检索证据或识别为个人医疗请求时，不进入普通教材生成流程。正常生成完成后，来源面板保留回答实际使用的来源；拒答时清空来源，避免旁边出现无关片段造成“回答已有证据”的错觉。关键词式边界检测有覆盖限制，系统提示和输出检查共同约束行为，但不能宣称完全解决了提示注入、幻觉或医疗安全问题。

密钥由本机设置接口保存于 `backend/.env`，读取设置时只返回是否已配置，原密钥不回传输入框。输入框使用密码类型，关闭弹窗清空未保存输入。第三方调用异常以通用错误提示呈现，避免把请求细节直接展示给用户。环境模板不含真实密钥，源码、测试、截图和评估摘要应与本机凭据、会话数据库及运行日志分开整理。

数据本地保存不意味着全部离线或绝不外传。使用 DeepSeek 时，问题、近期上下文和召回片段会发送到配置的模型服务；用户应仅使用允许用于该目的的学习资料。当前没有账号权限体系、加密备份或公网安全加固，不能直接把本地版本绑定公网地址作为正式在线服务。

当前中文资料包含 WHO 三本专业学习手册与一份中文心理健康教育指南，其许可在原书中逐项记录；英文 Open RN 教材还需保留单独标注的许可例外。`eval/chinese-books.json` 和 `eval/open-books.json` 保存来源、许可与文件指纹。系统不把任何聚合网站上的全部内容概括为同一种开放许可，也不导入盗版教材。

## 7. 测试设计、结果与解释边界

验证分为软件行为、真实资料映射和生成语义三个层次。自动化测试使用隔离数据库及专门生成的测试 PDF，检查接口与状态逻辑；真实资料测试使用独立核对的原页标签；医学结论是否被原文充分支持需要读者逐条审阅。三层结果相互补充，不能用其中一层替代其他层。

评估页提供三套题集：中文 11 题由 8 道教材题和 3 道资料外题构成；英文 13 题由 10 道教材题和 3 道资料外题构成；通用医学模板为 20 题，未绑定具体教材。绑定题集用文件指纹匹配资料版本，仅文件相同且就绪才适用预设页码。预期页不参与检索排序，只用于运行后的命中检查。

评估接口服务端记录的中文教材题首段耗时为 1.044-1.519 秒，总耗时为 1.238-2.158 秒。另一次首次学习问答的首段耗时为 3.094 秒，因此原需求中“所有请求首响应小于 3 秒”的目标尚不能作统一承诺。这里首段指经过格式检查后首次可展示的文本，不是模型收到请求后的第一个内部 token；该记录也不包含浏览器全部渲染耗时，网络、模型服务负载和本地预热均可能改变结果。

真实样本覆盖教材定义、连续追问、风险评估知识梳理、自测生成、资料外拒答和个人用药请求边界。网页实际检查了答案折叠、引用展开、PDF 原页、笔记下载、题集切换及刷新恢复。切换英文题集显示独立的未运行状态，返回中文题集可恢复 11 条结果，没有把中文成绩复制为英文成绩。

本轮未命中的教材题保留原有独立页码标准，没有根据返回结果改写标签。历史英文检索基准与本轮中文真实生成基准分开保留，不能把某次英文原页召回率用于证明中文跨语言能力。完整原始记录位于本机 `.local/acceptance/`，便于复核；可分发摘要为 `eval/competition-benchmark.json`，避免把大量原文和运行信息直接提交为公开代码。

2026-11-11 的运行包记录另验证启动与打包隔离，不替代上表的 AI 评测。`runtime/verification.json` 记录 39 项隔离检查通过，在 Windows PowerShell 5.1、从外部 TEMP 工作目录调用、PATH 不含 Node、外部 HTTP/HTTPS 代理不可用的条件下，原目录冷启动为 31.16 秒；同一电脑新路径运行包首次冷启动 139.31 秒，第二次冷启动 35.62 秒。启动日志未观察到外部 HTTP 请求，另核对 7 份资料、13,711 个片段、静态资源、原页 PNG、摘录及拒答，并在删除一次性测试会话后确认历史为空。

这些记录支持“同一台电脑搬到新目录、在所设离线限制下可启动和检索”的结论。它们不是物理断网、另一台实体电脑或真实 Windows 重启的结果；移包后也没有使用真实 DeepSeek Key 重做生成。不得把运行包首次 139.31 秒误写成问答响应时间。上述数值是有限次数的整服务启动样本，不是所有电脑的承诺。

本轮合并源码另外实测后端 39 项通过，耗时 5.76 秒。独立 ZIP 审计通过整包 SHA-256、CRC、104 个已跟踪源码与 b8c593f 的逐字节对应及选定资产哈希；manifest 汇总数比实际 ZIP 多 2 个文件、7,279,880 字节，原因未定，原运行包保持不变。该差异不应隐去，也不能据选定资产通过就声称整个 manifest 完全一致，详见 `submission/06-运行包核验说明.md` 与 `runtime-audit.json`。

API 返回的用量随消息和评估结果记录。费用栏依据 2026-10-11 的价格快照显示高峰单价估算，未知模型或缺少用量时不估算；停止或失败可能没有最终用量。本报告没有核验当前账单，不能据此证明每次调用的实际费用均小于 0.01 元。

## 8. 安装运行与结果复现

运行方式分为纯源码准备与完整评审运行包。纯源码在 Windows 上准备时需要 Python 3.11-3.13、Node.js 20.19+ 和网络，先双击 `prepare-medrag.cmd` 安装锁定依赖、构建网页及准备模型。准备完成后的日常启动不重新安装依赖或构建页面。完整评审运行包自带独立 Python 3.12.14、依赖、前端成品、BGE 模型、7 份指定公开资料和无个人会话的索引，日常使用不要求系统安装 Node.js。

先将 `MedRAG-Review-20261111.zip` 完整解压到可写目录，勿在压缩包预览窗口内直接启动。双击 `check-medrag.cmd` 可离线检查 Python、核心依赖、页面资源和本地模型文件；它不启动服务、不写会话库，也不代表已经完成模型推理或 API 验证。随后双击 `start-medrag.cmd`，待服务健康检查及首页检查通过后，浏览器自动打开 `http://127.0.0.1:8000/`。默认最长等待 300 秒，期间显示进度；冷启动可能明显长于日常问答。

启动器使用项目标识和健康接口识别本目录服务，重复点击可复用已经启动的服务；仍在加载的有效进程也会保留，避免重试造成多个后端。8000 端口被其他程序或另一份项目占用时，会报告冲突，不杀死未知进程。启动失败保留窗口并记录 `.local/launcher.log`，服务日志为 `.local/server.log` 与 `.local/server-error.log`。双击 `stop-medrag.cmd` 停止本目录服务。真实电脑重启尚未实测；按启动设计，系统重启后需再次运行启动入口。

在网页右上角“配置 API Key / API 设置”保存使用者自己的 DeepSeek 密钥，无需重启或重建索引；完整运行包不含开发者密钥。生成式讲解、知识梳理和自测需要网络与有效 Key。无 Key 时只能使用标明的原文摘录、检索、来源及 PDF 原页，不应把它描述为 DeepSeek 生成验证。导入有权限的文字版 PDF 后，填写来源与许可，再建立索引；新增文件、更换内容或检索方式需重新入库。

纯源码包排除模型、运行依赖、原始教材和本机会话；需要书籍时可通过 `download-demo-books.cmd` 与 `download-chinese-books.cmd` 从清单所列来源准备。完整评审运行包则按公开书目白名单包含指定 PDF、许可说明及可迁移索引。构建记录明确源码取自已提交的 `b8c593f`，即使构建工作区另有修改，也不把那些修改当作运行包源码。实际用户环境文件未复制，`conversation`、`message`、`feedback` 初始为空；运行包内的环境模板仅供接收者配置。

开发者可在项目根目录运行以下检查，API 实验应另标日期与配置，不将本机历史成绩自动视作移包后成绩。

## 9. 技术组合与应用价值

本项目的实现重点是把证据追溯放入学习动作本身。来源编号连接原文快照与经过指纹检查的 PDF 物理页，学生可在同一界面从解释回到教材。文件改变后保留历史文字、阻止错误原页跳转，有助于区分“历史回答曾基于什么资料”和“当前文件是什么版本”这两个问题。

讲解、梳理和自测共用同一证据约束，复习材料无需离开来源体系另行生成。自测的题干与参考答案也保留引用，读者可以先回忆，再展开答案并核对出处。会话导出把学习结果、许可和指纹一起带出页面，使笔记仍保有可识别的来源线索，而不只是一段脱离教材的聊天文本。

可观察的执行过程和分层评估提高了结果的可解释性。用户能看到检索耗时、实际使用的引用和生成检查状态；评估分别报告原页命中、资料外拒答与人工引用准确率。页面没有将检索排序分包装成答案置信度，也没有为尚未核验的医学结论预先展示准确率。

上述价值是当前系统实现与交互设计的贡献，不是对学术首创、医学有效性、学习成绩提升或商业可行性的证明。当前没有对照试验、用户学习效果研究或付费运营数据。后续若验证教育收益，需要在授权资料与明确任务上开展用户测试，同时保存操作成本、核对耗时及错误修正情况。

## 10. 总结、后续工作与依据

当前版本完成了本地资料管理、混合检索、证据限定生成、引用原页、连续学习、自测、会话保存与评估导出的主要链路。已有记录支持软件行为和来源映射的可检查性，真实生成样本说明当前配置能够完成选定任务；这仍不足以证明所有医学解释正确、所有查询都可召回、所有网络条件下都满足性能与费用目标。

下一步首先补齐人工语义核验：固定题目和资料版本，由审阅者逐条核对结论、引用与适用范围，记录错误类型。随后在不修改独立原页标准的条件下，评估同义词、缩写、跨语言及跨页内容；对检索漏召回、保守拒答和引用解读错误分别改进。扫描件 OCR、复杂表格、更多教材与更广设备兼容需独立验证后再列入实现范围。
